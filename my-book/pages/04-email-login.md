# 04. 이메일과 비밀번호로 로그인하기

## 학습 목표

- 회원가입과 로그인이 서로 다른 작업임을 설명한다.
- 이메일 확인이 필요한 경우 세션이 즉시 생기지 않는 이유를 이해한다.
- Auth 사용자와 앱 프로필 데이터를 구분한다.

회원가입은 새 계정을 만드는 작업이고, 로그인은 이미 있는 계정의 이메일과 비밀번호를 검사해 세션을 만드는 작업이다. Supabase Auth는 비밀번호를 안전한 형태로 관리한다. `public.users` 테이블에 비밀번호를 직접 저장하면 안 된다.

이메일 확인이 켜져 있으면 가입 직후 인증 메일이 발송된다. 사용자가 링크를 누르기 전에는 `signUp`이 성공해도 세션이 없을 수 있다. 이때 앱이 무조건 메인 화면으로 보내면 다시 로그인 화면으로 돌아오는 혼란이 생긴다.

```text
회원가입 요청
  → auth.users 계정 생성
  → 인증 메일 발송
  → 사용자가 링크 클릭
  → 이메일 확인 완료
  → 이메일+비밀번호 로그인
  → 세션 생성
```

## 비밀번호 입력 기본 규칙

HTML의 `type="password"`는 화면에서 글자를 가릴 뿐 전송과 저장 보안을 모두 해결하는 것은 아니다. HTTPS를 사용하고 Supabase Auth에 비밀번호 처리를 맡긴다. 예제 입력의 `minLength={6}`은 브라우저 최소 검사이며 서비스 보안 정책은 Supabase 설정과 함께 정해야 한다.

3. 비밀번호를 `public.users`에 저장하면 안 되는 이유를 쓰시오.
