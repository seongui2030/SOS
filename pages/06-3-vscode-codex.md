# 06-3. VS Code에 Codex 연결하기

## Codex IDE 확장 설치

이 절은 [공식 OpenAI Codex IDE 문서](https://learn.chatgpt.com/docs/codex/ide)를 기준으로 한다. 제품 화면과 이용 가능 기능은 계정과 시점에 따라 달라질 수 있다.

1. VS Code를 실행한다.
2. 왼쪽 Extensions 아이콘을 누르거나 `Ctrl+Shift+X`를 누른다.
3. `Codex`를 검색해 OpenAI가 제공하는 확장을 확인한다.
4. Install을 누른다.
5. 왼쪽 Codex 아이콘을 연다.
6. 아이콘이 없으면 `Ctrl+Shift+P`를 누르고 `Codex: Open Codex Sidebar`를 실행한다.
7. 안내에 따라 계정으로 로그인한다.
8. VS Code에서 프로젝트 폴더 `C:\SOS`를 연다.

공식 문서에 따르면 VS Code와 호환 편집기에서는 Codex 확장을 사용하고, 열린 파일과 선택한 코드 같은 편집기 문맥을 대화에 포함할 수 있다. 수정 결과는 에디터 옆에서 diff로 검토할 수 있다.

## 첫 요청 연습

파일을 수정하지 않는 요청부터 시작한다.

```text
현재 프로젝트의 package.json과 폴더 구조를 분석해 주세요.
아직 파일을 수정하지 말고 고등학생이 이해할 수 있게 설명해 주세요.
```

이 문장에는 범위, 금지 행동, 설명 수준이 들어 있다. AI가 작업 의도를 더 정확히 이해한다.

수정 요청은 결과와 검증을 함께 쓴다.

```text
src/routes/auth.tsx에서 이메일 확인 전에는 메인 화면으로
이동하지 않도록 수정해 주세요. 다른 로그인 기능은 유지하고,
수정 후 npx tsc --noEmit으로 검사해 주세요.
```

## 편집기 문맥 사용

오류가 난 줄을 선택하고 질문하면 전체 파일을 복사하지 않아도 된다. 다만 오류는 위쪽 괄호 때문에 발생할 수 있으므로 관련 함수 전체를 함께 열어 둔다. 비밀 키가 선택된 `.env.local` 화면은 질문에 첨부하지 않는다.

## 권한과 승인

Codex가 파일을 읽는 작업, 수정하는 작업, 터미널 명령, 인터넷 접근은 영향이 다르다. 삭제, 배포, 패키지 설치, 외부 서비스 변경은 대상을 확인한 뒤 승인한다. `git reset --hard`, 강제 push, 광범위한 삭제 명령은 복구 위험이 크다.

## 설치 확인

- [ ] Codex 사이드바가 열린다.
- [ ] 계정 로그인이 완료된다.
- [ ] 현재 workspace가 `C:\SOS`인지 확인한다.
- [ ] 열린 파일을 설명해 달라는 요청에 답한다.
- [ ] 수정 요청 전 Git 상태를 확인한다.
