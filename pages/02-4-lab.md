## 실습 A: 환경변수 분류하기

다음 값에 대해 브라우저 공개 가능 여부와 저장 위치를 정한다.

| 값 | 브라우저 | 로컬 파일 | Vercel 유형 |
|---|---|---|---|
| Supabase Project URL | 가능 | `.env.local` | Config |
| Supabase Publishable key | 가능 | `.env.local` | Config 또는 Secret |
| Supabase Service role key | 불가 | 서버 환경 | Secret |
| Google Client Secret | 불가 | Supabase 설정 | Secret |
| 개인 Access Token | 불가 | 안전한 자격 증명 저장소 | 보통 앱 변수 아님 |

“Secret을 선택했다”와 “브라우저에서 비밀이다”는 같은 말이 아니다. `VITE_` 변수는 Vercel UI에서 Secret으로 가려도 빌드된 브라우저 코드에 포함될 수 있다.

## 실습 B: 연결 오류 추리

상황 1: 로컬은 성공하지만 Vercel에서 `Missing Supabase environment variable(s)`가 보인다.

가능한 원인은 Production 범위에 VITE 변수가 없거나, 저장 후 재배포하지 않았거나, 변수 이름이 틀린 것이다. Supabase 테이블을 다시 만드는 것은 첫 조치가 아니다.

상황 2: `auth/v1/user`는 200인데 `conversations`가 404다.

로그인은 성공했다. 연결된 Supabase 프로젝트에 테이블이 없거나 잘못된 프로젝트 URL을 사용 중일 가능성이 크다.

상황 3: 테이블 요청이 403이다.

테이블은 있지만 권한이 거부되었다. 세션, GRANT, RLS 정책과 행의 `user_id`를 확인한다.

## 실습 C: 안전한 질문 만들기

다음 위험한 질문을 안전하게 바꿔 보자.

```text
내 .env 전체 내용은 다음과 같아: [실제 키들]
왜 연결 안 돼?
```

안전한 예:

```text
.env.local에 VITE_SUPABASE_URL과
VITE_SUPABASE_PUBLISHABLE_KEY가 있습니다. 값은 가렸습니다.
브라우저 Console에는 다음 오류가 납니다: [오류].
변수 이름과 읽는 코드를 비교해 주세요. 파일은 수정하지 마세요.
```

## 형성평가

1. 같은 Project URL을 두 환경변수에 넣는 이유를 설명하시오.
2. `VITE_` 접두사가 갖는 의미를 쓰시오.
3. publishable key가 있어도 다른 사람의 데이터를 읽지 못하게 하는 기능은 무엇인가?
4. 이미 Git에 올라간 service role key에 해야 할 조치는 무엇인가?
5. URL과 key가 서로 다른 프로젝트 값이면 어떤 혼란이 생길 수 있는가?
